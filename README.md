# TenderLens KZ

Локальное приложение на Python для поиска и объяснения необычно высоких цен в закупках офисной бумаги. Загружает CSV, подбирает прошлые сопоставимые покупки, сохраняет результаты в SQLite и показывает аналоги в браузере.

В комплекте 33 синтетические позиции для проверки алгоритма и небольшой пилот из настоящих договоров Казахстана. Раздел «Реальные закупки» загружает публичные карточки без токена и поддерживает официальный API с токеном. Практическая полезность обнаружения аномалий на большой реальной выборке пока не проверена. Срабатывание ценового правила не является заключением о нарушении.

## Установка и запуск

Нужен Python **3.11 или новее**; проект проверен на Python 3.12. Системный Python 3.9 не подходит. Клонируйте репозиторий и создайте окружение:

```bash
git clone https://github.com/sigmabotyyyyyyy/tenderlens-kz.git
cd tenderlens-kz
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]' -c requirements-lock.txt
python -m streamlit run app.py
```

На Windows вместо двух команд создания и активации окружения используйте `py -3.12 -m venv .venv` и `.venv\Scripts\Activate.ps1` в PowerShell. Остальные команды выполняются в корне проекта с активированным окружением. `python3.12` можно заменить на установленный Python 3.11+.

На macOS после `chmod +x run.command` также можно открыть `run.command` двойным щелчком. Скрипт проверяет окружение и запускает приложение из папки проекта.

Откройте http://localhost:8501 и нажмите **«Загрузить демо и выполнить анализ»**. Набор выбирается в боковой панели. В рабочей области доступны параметры, сводка, поиск, фильтры и карточка ручной проверки. Раздел «Метод сравнения» объясняет расчёт, раздел «Загрузка данных» принимает следующий CSV.

Экран **«Идея и заработок»** показывает четыре блока: идея, предполагаемые клиенты, способы заработка и окупаемость. Откройте http://127.0.0.1:8501/?view=business или выберите раздел в меню. Калькулятор принимает число платящих клиентов, цену, постоянные и переменные расходы, вложения, оплату своего труда и произвольный резерв из выручки. Он показывает выручку, прибыль после указанных расходов, число клиентов для покрытия расходов и простой срок возврата вложений с округлением вверх до месяца. При убытке окупаемость не обещается. Начальные числа — учебные допущения; вероятность заработка и платёжный спрос пока не измерены. Сценарий можно скачать в CSV. Этот экран не меняет анализ закупок.

Для настоящих закупок откройте **«Реальные закупки» → «Открыть реальный пилот» → «Импортировать проверенные позиции»**. Две позиции готовы, третья требует уточнений. После запуска анализа ожидается «Мало аналогов»: пилот не содержит 20 сопоставимых прошлых договоров. Загрузка новых карточек и получение API-токена описаны в [руководстве по реальным данным](docs/REAL_DATA.md).

Также доступна **«Расширенная реальная выборка»**: из 160 карточек получены 163 позиции, готовы 18 позиций из разных договоров, 145 требуют уточнений. Откройте расширенную выборку, импортируйте проверенные позиции и выполните анализ. В сохранённом эксперименте максимум найден 1 аналог; этого недостаточно для решения при минимуме 20. Дальнейший поиск ограничен CAPTCHA портала. Подробности и файлы — в [отчёте о сборе](reports/REAL_COLLECTION.md).

После клонирования локальная база создаётся заново: прежние наборы, комментарии и запуски в репозиторий не включены. Демо и подготовленные реальные данные входят в репозиторий, поэтому их можно импортировать без токена и без подключения к порталу.

Проверка без браузера:

```bash
.venv/bin/python -m tenderlens demo
```

## Что проверить в демо

| Позиция | Ожидаемый результат |
| --- | --- |
| TARGET-HIGH | Цена 3000 ₸, медиана 1800 ₸, +66.7%, выделена |
| TARGET-NORMAL | Цена 1800 ₸, без срабатывания |
| TARGET-BOUNDARY | Цена 2700 ₸, +50.0%, выделена на границе порога |
| TARGET-BELOW | Цена 2699.99 ₸, ниже точной границы, без срабатывания |
| TARGET-PACK250 | Другая упаковка, недостаточно данных |
| FUTURE-HIGH | Отдельная поздняя закупка; не влияет на расчёт февральских целей |

Всего в демо: **3 выделенных позиции, 2 без срабатывания, 28 с недостатком данных**. Ранние закупки ещё не имеют 20 прошлых договоров — это ожидаемо.

У TARGET-HIGH 20 договоров-аналогов и 21 исходная строка: один договор содержит две позиции и учитывается только один раз. Ожидаемые результаты заданы вручную в [expected_results.json](data/demo/expected_results.json).

Для проверки ошибок загрузите [paper_invalid.csv](data/demo/paper_invalid.csv) как синтетический набор. Ожидается одна принятая строка и пять отклонённых.

Прямые зависимости зафиксированы в pyproject.toml; полный набор проверенных версий — в requirements-lock.txt. Системный Python 3.9 для этого проекта не подходит.

## Как показать проект учителю

1. **Идея:** программа помогает отбирать закупки с необычно высокой ценой для ручной проверки. Анализируется цена пачки бумаги с известными характеристиками.
2. **Реальные данные:** покажите источник, 18 принятых позиций и причины отклонения остальных. Статус «Мало аналогов» означает нехватку сопоставимых прошлых договоров.
3. **Работа алгоритма:** загрузите демо, откройте `TARGET-HIGH` и покажите 20 договоров-аналогов, медиану 1800 ₸ и цену 3000 ₸. Превышение +66.7% больше порога +50%.
4. **Бизнес-модель:** откройте «Идея и заработок», объясните предполагаемых клиентов, подписку и расчёт окупаемости. Числа в калькуляторе — сценарий, а не подтверждённые продажи или прогноз дохода.

Срабатывание на демо проверяет реализацию правила. На опубликованной реальной выборке качество обнаружения аномалий пока не измерено.

## Работа со своим CSV

Формат и обязательные поля описаны в [ТЗ](docs/TECH_SPEC.md). Загружаются цены одной пачки бумаги в тенге. Требуются формат бумаги, плотность, число листов, количество пачек, дата договора, регион и условия включения НДС и доставки. Для реального набора обязательна исходная HTTPS-ссылка.

В браузере выберите «Загрузка данных», затем тип набора и файл. После сохранения запустите анализ. Можно менять окно истории, минимум договоров и ценовой порог. Фильтры отображения не изменяют сохранённый состав аналогов. Снятие всех статусов даёт пустую выборку; кнопка сброса возвращает исходные условия.

Из командной строки:

```bash
.venv/bin/python -m tenderlens analyze data/demo/paper_demo.csv --kind synthetic --output reports/demo_results.csv
```

Для сохранения причин отклонения строк добавьте `--errors reports/import_errors.csv`. Такой файл создаётся и при полностью некорректном наборе. Установленный пакет содержит встроенное демо и работает вне исходного проекта.

Для реального файла укажите `--kind real`. Дополнительные параметры: `--window 180`, `--min-contracts 20`, `--threshold 1.50`, `--db путь/к/базе.sqlite3`.

CSV ограничен 10 МиБ и 5000 строками. Ошибочные строки не участвуют в анализе. Позиции одного договора должны иметь одну дату, заказчика и поставщика; конфликтующий договор целиком отклоняется. HTTPS-ссылки проверяются вместе с портом; учётные данные и обратные слеши в ссылках не принимаются.

Повторная загрузка того же файла открывает сохранённый набор. В браузере одинаковые параметры переиспользуют готовый запуск; новые параметры создают отдельный. CLI выполняет отдельный запуск при каждом вызове. Пассивное обновление страницы ничего не записывает.

## Как считается результат

Аналоги совпадают по формату, плотности, упаковке, единице, валюте, НДС, доставке и региону. Количество должно составлять 0.5–2 объёма целевой покупки. Используется история за 180 дней по умолчанию; текущий день, будущие закупки и свой договор исключаются.

Сначала считается медиана подходящих позиций внутри каждого чужого договора, затем медиана этих договорных цен. Если договоров меньше 20, результат — `insufficient_data`.

```text
ratio = цена позиции / медиана договорных цен
отклонение = (ratio - 1) × 100%
flagged, если цена >= медиана × порог
```

Решение принимается до округления. Отображение +50.0% само по себе не означает достижения точного порога: например, 2699.99 ₸ остаётся ниже 2700 ₸. Условия сравнения, параметры и исходные аналоги доступны в карточке.

## Проверки и эксперименты

```bash
.venv/bin/python -m pytest
.venv/bin/python -m scripts.generate_demo
.venv/bin/python -m scripts.evaluate --benchmark
```

Генератор воспроизводит демофайлы и вручную заданные ожидания. Эксперимент сравнивает подбор аналогов с базовым методом, меняет только цены выбранных контрольных целей и измеряет обработку 5000 строк, включая сохранение аналогов в SQLite.

Результаты: [отчёт](reports/evaluation.md), [машиночитаемые результаты](reports/evaluation.json). Измеряются два профиля: 10 групп и одна плотная группа с 11,484 млн связей аналогов. У каждого процесса отдельно измеряются время, пиковая память и размер базы. При запуске эксперимента отчёты обновляются фактическими измерениями.

## Структура и хранение

```text
app.py                  # интерфейс Streamlit
config.py               # пути к демо и локальной БД
tenderlens/
  models.py             # структуры и параметры
  numeric.py            # точная денежная медиана
  paths.py              # путь к локальной базе
  validation.py         # строгая проверка CSV
  comparables.py        # индекс истории и подбор аналогов
  analysis.py           # цены, статусы, объяснения
  business.py           # расчёт учебного бизнес-сценария
  storage.py            # транзакции SQLite
  service.py            # импорт, анализ, подготовка таблиц
  export.py             # CSV результатов и ошибок
  demo.py               # воспроизводимые примеры
  cli.py                # командная строка
  ui/                   # загрузка, результаты и карточка
  sources/              # публичный реестр, API и подготовка данных
data/demo/              # синтетические CSV и ожидания
data/real/              # подготовленная выборка и происхождение данных
scripts/                # генерация и оценка
tests/                  # проверки алгоритма, импорта, БД и интерфейса
reports/                # результаты эксперимента
docs/                   # ТЗ и план
```

Локальная БД `data/app.sqlite3` исключена из Git. Результаты, их параметры, аналоги и ручные проверки сохраняются после перезапуска. Для отдельной базы задайте `TENDERLENS_DB`; в CLI явный `--db` имеет приоритет. Путь по умолчанию относится к текущей рабочей папке, а не к установленному пакету.

База первой реализации автоматически и транзакционно обновляется до схемы 2 с сохранением комментариев и старых запусков. Связи аналогов хранят числовые ключи, результаты рассчитываются и записываются по одной позиции; таблица результатов загружается без всех связей, доказательства читаются для выбранной карточки.

Подключение реальных данных, правила преобразования и ограничения описаны в [docs/REAL_DATA.md](docs/REAL_DATA.md). Следующий этап — расширить реальную выборку и выполнить ручную оценку алгоритма; массовый обход портала и машинное обучение в эту версию не входят.

## Что входит в публичный репозиторий

Исходный код, тесты, документация, синтетические примеры, подготовленные данные из публичных карточек [портала госзакупок Казахстана](https://goszakup.gov.kz/) и отчёты. У реальных записей сохранены ссылки на источники; идентификаторы участников в подготовленных данных заменены хешами названий. Выборка отражает состояние источников на момент сбора и не гарантирует полноту реестра.

Локальная SQLite-база, `.venv`, API-токены, `.env`, Streamlit secrets и кэш исходных HTML/PDF исключены из Git. Для сохранённых CSV токен не нужен; для официального API пользователь задаёт свой токен по инструкции в `docs/REAL_DATA.md`.
